# TimeAudit — инструкция пользователя

TimeAudit проверяет трудозатраты сотрудников из выгрузки Jira, показывает найденные замечания и формирует итоговый Excel-отчёт.

## 1. Что понадобится

Перед началом подготовьте:

- файл `TimeAudit.exe`;
- исходную выгрузку из Jira **Time Sheet Report** в формате `.xls`;
- при проверке инвест-направлений — один или несколько CSV-файлов из GBS JIRA с полями `Issue key` и `Custom field (BUH Company)`.

Для правильного сравнения с нормой часов загружайте полный отчёт за календарный месяц. Текущая версия программы использует производственные календари только за 2026 год.

## 2. Как запустить приложение

1. Поместите `TimeAudit.exe` в отдельную папку на компьютере. Устанавливать программу не нужно.
2. Дважды щёлкните по `TimeAudit.exe`.
3. Подождите несколько секунд. Откроется чёрное служебное окно, а затем браузер со страницей TimeAudit.
4. Не закрывайте чёрное окно, пока работаете с программой. Если закрыть его, приложение остановится.

При первом запуске рядом с `TimeAudit.exe` автоматически появится папка `data`. В ней программа хранит свою базу данных и загруженные сведения. Не удаляйте и не переименовывайте эту папку, если хотите сохранить данные.

Если браузер не открылся автоматически, найдите в чёрном окне строку вида `Open in your browser: http://127.0.0.1:8001/` и откройте указанный адрес вручную.

При первом запуске Windows может показать предупреждение о неизвестном приложении. Запускайте файл только в том случае, если получили его из доверенного источника.

Чтобы завершить работу, закройте вкладку браузера, а затем чёрное служебное окно.

## 3. Как пользоваться приложением

### Шаг 1. Загрузите выгрузку Jira

1. На странице TimeAudit перетащите файл Time Sheet Report в область загрузки или нажмите **«Выбрать файл»**.
2. Дождитесь появления названия файла, количества записей и отметки **«загружено»**.
3. Просмотрите загруженные строки в таблице. Можно отфильтровать их по сотруднику, проекту, ключу задачи и датам.

На экране одновременно показывается не более 100 строк. Если записей больше, используйте фильтры. Это ограничение касается только просмотра: проверяются все загруженные строки.

### Шаг 2. При необходимости запустите проверку времени

Проверка логов **необязательна**. Если нужно только распределение по инвест-проектам, этот шаг можно пропустить и сразу перейти к шагу 3.

1. Нажмите **«Запустить проверку»**.
2. Дождитесь окончания проверки. Она может занять несколько минут, особенно если включена проверка комментариев с помощью ИИ.
3. После завершения появится таблица **«Результаты проверки»**.

В таблице для каждого сотрудника показаны:

- **Факт, ч** — сколько часов найдено в выгрузке;
- **Норма, ч** — норма рабочего времени по производственному календарю;
- **Разница** — факт минус норма;
- **Статус** — итог проверки;
- **Замечания** — количество найденных типов проблем.

Значение статусов:

- **OK** — замечаний не найдено;
- **Внимание** — есть предупреждения, которые нужно проверить;
- **Ошибка** — найдено хотя бы одно нарушение.

Нажмите на строку сотрудника, чтобы раскрыть список замечаний и увидеть пояснения.

### Шаг 3. При необходимости заполните инвест-направления

Блок **«Распределение по проектам»** появляется сразу после загрузки файла. Проверка времени для этого не нужна. Используйте блок только для сотрудников, которых нужно включить в инвест-анализ.

1. Если у вас есть CSV-выгрузки из GBS JIRA, загрузите их в поле **«Загрузка CSV файлов BUH Company»**. Можно выбрать сразу несколько файлов.
2. Проверьте сообщение с количеством определённых и неопределённых ключей.
3. Отметьте нужных сотрудников и нажмите **«Далее»**.
4. Просмотрите автоматическое распределение:
   - строки **«Автоматическое распределение (100%)»** уже полностью отнесены к указанному инвест-проекту;
   - строки **«По BUH Company (из CSV)»** определены по данным дополнительной выгрузки.
5. Заполните строки, требующие решения:
   - в разделе **«Ручное распределение (процент)»** укажите процент часов и инвест-проект;
   - в разделе **«Ручное назначение проекта»** выберите проект, к которому относятся все часы задачи.
6. Нажмите **«Сохранить»**.
7. Проверьте итоговую сводку по проектам и сотрудникам.

Если ключ не найден в CSV или значение BUH Company не распознано, программа попросит назначить инвест-проект вручную.

### Шаг 4. Скачайте отчёт

Нажмите **«Скачать отчёт»**. Браузер загрузит Excel-файл с названием вида `TimeAudit_Report_1.xlsx`. Отчёт можно скачать сразу после загрузки файла, даже если проверка времени не запускалась.

В отчёте находятся:

- **«Сводка»** — факт, норма, разница, статус и количество замечаний по сотрудникам;
- **«Распределение»** — часы по проектам, сотрудникам и странам;
- **«Инвест-направления»** — автоматическое и ручное распределение инвест-часов;
- **«Простои GENERAL-122»** — сведения о времени, списанном на задачу простоя;
- **«Ошибки»** — общий список найденных ошибок и предупреждений;
- **«Недобор часов»** — сотрудники с часами ниже нормы;
- отдельный лист для каждого сотрудника с его трудозатратами и замечаниями.

Если проверка времени не запускалась, в листе «Сводка» статус будет **«Не проверялось»**, а листы «Ошибки» и «Недобор часов» будут пустыми. Лист «Инвест-направления» заполняется по сохранённому распределению.

Если после проверки вы изменили инвест-распределение, скачайте отчёт ещё раз, чтобы в нём были последние сохранённые данные.

## 4. На основании чего происходит проверка

### 4.1. Разрешённые задачи

Программа использует встроенный справочный Excel-файл со списком правил.

Для каждой строки трудозатрат она сначала ищет правило по точному ключу Jira, например `BUH-12345`. Если отдельного правила для ключа нет, проверяется общее правило для сочетания **проект + тип задачи**.

В справочнике учитываются:

- разрешено или запрещено списывать время на задачу;
- сотрудники-исключения, которым задача запрещена;
- сотрудники, которым одним разрешено использовать задачу;
- правила проверки комментариев;
- правила распределения по инвест-направлениям.

Если задача не найдена ни по ключу, ни по сочетанию проекта и типа, она считается неразрешённой.

Важно: текущая сборка использует справочник, который был встроен в `TimeAudit.exe` при создании программы. Изменение другого Excel-файла рядом с программой не обновит правила внутри уже собранного файла.

### 4.2. Норма рабочего времени

Фактические часы каждого сотрудника суммируются отдельно за каждый месяц и сравниваются с полной месячной нормой для его страны:

- Россия — `RU`;
- Казахстан — `KZ`;
- Беларусь — `BY`.

Используется производственный календарь 2026 года для пятидневной 40-часовой рабочей недели с учётом официальных праздников и сокращённых предпраздничных дней.

- Недобор более чем на 0,5 часа считается ошибкой.
- Перебор более чем на 0,5 часа считается предупреждением.
- Разница меньше 0,5 часа не выводится как замечание.

Страна сотрудника берётся из встроенного списка. Если сотрудника в списке нет, программа применяет календарь России. Поэтому неожиданные значения нормы нужно дополнительно проверить.

Программа сравнивает данные с полной нормой месяца. Она не уменьшает норму автоматически из-за неполного периода выгрузки, индивидуального графика или отсутствия сотрудника. Отпуск, больничный и отгул должны быть корректно отражены в Jira.

### 4.3. Качество комментариев

Если для задачи не установлено послабление, программа отмечает как ошибку:

- пустой комментарий;
- стандартный комментарий Jira, например `Working on issue ...`;
- комментарий короче 10 символов;
- комментарий, полностью совпадающий с названием задачи.

Для отдельных задач в справочнике может быть разрешён пустой или короткий комментарий. Также предусмотрены специальные короткие формулировки для нескольких конкретных ключей.

### 4.4. Соответствие комментария задаче

Если в сборке настроен доступ к сервису ИИ и есть интернет, программа дополнительно сравнивает смысл комментария с проектом, типом и названием задачи.

- зелёный результат не создаёт замечание;
- сомнительный результат создаёт предупреждение;
- несоответствие создаёт ошибку.

Пустые, явно неправильные и разрешённые справочником комментарии повторно через ИИ не проверяются. Если сервис ИИ недоступен, этот этап пропускается, а остальные проверки продолжают работать.

### 4.5. Лимит времени для специальных задач

Для задач `BUH-72900` и `BUH-115258` действует общий месячный лимит:

**20 минут × количество рабочих дней месяца.**

Если суммарные часы сотрудника по этим задачам превышают лимит, программа показывает предупреждение.

### 4.6. Общие правила списания

Программа отдельно проверяет два правила:

- записи с упоминанием ВГ, ВГО, внутригрупповой работы или СД должны быть списаны на `BUH-71413`;
- больничный, отпуск и отгул нельзя списывать на проект `HR` — для них должен использоваться проект `GENERAL`.

Нарушение этих правил считается ошибкой.

### 4.7. Инвест-направления

Распределение инвест-часов не определяет статус основной проверки. Это отдельная часть отчёта.

Способ распределения задаётся встроенным справочником:

- 100% часов автоматически относятся к указанному проекту;
- пользователь вручную задаёт процент;
- пользователь вручную выбирает проект для всех часов;
- проект определяется по BUH Company из загруженного CSV, а при отсутствии совпадения назначается вручную.

## 5. Если что-то не работает

- **Страница закрылась или перестала отвечать.** Проверьте, открыто ли чёрное служебное окно. Если оно закрыто, снова запустите `TimeAudit.exe`.
- **Файл не загружается.** Убедитесь, что это исходная выгрузка Time Sheet Report из Jira в формате `.xls` с нужными столбцами, а не вручную изменённая таблица.
- **Норма часов выглядит неверно.** Проверьте, что выгрузка содержит полный месяц 2026 года и сотруднику назначена правильная страна.
- **Проверка комментариев занимает много времени.** Не закрывайте приложение. ИИ-проверка зависит от скорости интернета и внешнего сервиса.
- **Отчёт не скачивается.** Разрешите браузеру открытие новой вкладки и повторно нажмите **«Скачать отчёт»**. Не скачивайте отчёт, пока идёт проверка времени — дождитесь её окончания.
- **Данные инвест-направлений не попали в отчёт.** Сначала нажмите **«Сохранить»** в блоке инвест-направлений, затем скачайте отчёт заново.
